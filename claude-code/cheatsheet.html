対象可否配り方

C3つの鉄則

✅ deny は揃える破壊的コマンド（rm -rf）と秘密情報の Read 禁止を全員に。事故防止効果が最大。
🚫 シークレットを共有に書かないパスワード・トークンは settings.local.json へ。
💡 絶対パスは共有に書かない/Users/... は local へ。共有では **/ パターンで一般化。

Dコピペ用サンプル（要点）

① ユーザー 各自

~/.claude/settings.json
"allow": [
  "Bash(git log:*)",
  "Bash(git diff:*)",
  "Bash(ls:*)", "Bash(cat:*)",
  "Bash(grep:*)", "Bash(rg:*)",
  "Bash(jq:*)", "Bash(find:*)",
  "Bash(gh pr view:*)",
  "Bash(gh pr diff:*)"
],
"deny": [ "Bash(sudo:*)" ]
  • 横断的に安全な読取専用だけ
  • 許可ダイアログが激減

② 共有 commit

.claude/settings.json
"deny": [
  "Bash(rm -rf:*)",
  "Bash(git push --force:*)",
  "Bash(chmod 777:*)",
  "Bash(sudo:*)",
  "Read(.env)", "Read(.env.*)",
  "Read(**/*.pem)",
  "Read(**/*.key)",
  "Read(**/credentials.yml.enc)"
]
  • + そのリポの安全コマンドを allow
  • + main直push禁止 hook（下記E）

③ 個人 gitignore

.claude/settings.local.json
"allow": [
  "Bash(gh pr view:*)",
  "Read(/Users/<name>/.rbenv/**)",
  "Read(/opt/homebrew/bin/**)"
],
"env": {
  "MYSQL_PASSWORD": "..."
}
  • 絶対パスは先頭 / 1つ
  • パスワード等はここだけ

Eそのリポの安全コマンドを allow（言語別）

🛤 Rails

// bin 運用
"Bash(bin/rspec:*)", "Bash(bin/rubocop:*)",
"Bash(bin/rails:*)", "Bash(bin/rake:*)"
// bundle 運用
"Bash(bundle exec rspec:*)"

⚛ フロント（npm）

"Bash(npm run lint:*)",
"Bash(npm run test:*)",
"Bash(npm run typecheck:*)",
"Bash(npm run build:*)"

Fmain 直push を止める hook（共有 settings.json）

"hooks": { "PreToolUse": [{ "matcher": "Bash", "hooks": [{
  "type": "command",
  "command": "CMD=$(echo \"$TOOL_INPUT\" | jq -r '.command // empty'); if echo \"$CMD\" | grep -Eq 'git push .*(origin )?(main|master)\\b'; then echo '{\"block\":true,\"reason\":\"main直pushは禁止。PRを作成してください\"}'; exit 2; fi; exit 0"
}]}]}

Gよくある間違い

症状原因対処
local の Read 許可が効かない先頭スラッシュが //（2つ）/Users/... に直す
他人の環境で hook が壊れる絶対パスをハードコード$CLAUDE_PROJECT_DIR / $HOME
秘密情報が git に乗ったenv を共有に記載local へ移し履歴から除去
許可ダイアログが多すぎる安全コマンド未許可① か ② の allow に追加
gh で意図せず書き込みgh:* 全許可gh pr view 等に絞る
